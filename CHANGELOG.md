## v0.9.0 — 2026-09-14

## MyHeritage-style consistency checks

gedlint now runs the same class of checks the MyHeritage Tree Consistency Checker runs on your online tree, locally and offline. Nine gap items compared against that tool's 36 checks:

**In core, on by default**

- **W310 extended**: any dated fact (`OCCU`, `RESI`, `CENS`, `EMIG`, ...) before a birth or after a death is an error. This was MyHeritage's largest warning group (156 "fact after death" on one user's tree): record hints attach to the wrong person and nothing tells you. Citation publication years (`RESI -> SOUR -> DATA -> DATE`) are correctly ignored.

**Opt-in `hygiene` ruleset (W705-W712)**

- **W705** alive but too old: no death recorded and the birth is more than 110 years before the file's newest date.
- **W706** large spouse age difference (threshold 25 years).
- **W707** married too young (threshold 16), plus a spouse who died in childhood.
- **W708** siblings sharing a first name: duplicate or namesake, worth one look.
- **W709** individuals connected to no family: the leftovers of a deleted branch.
- **W710** double spaces, `Dr.` in the given name, `Jr.` in the surname, 2-digit years, missing SEX.
- **W711** children of one family carrying different surnames.
- **W712** causes of death (`Holocaust`) and dates inside place names.

Nothing fires unless you enable `hygiene`, and every threshold is configurable:

```toml
[lints]
presets = ["recommended", "hygiene"]

[lints.thresholds]
max-alive-years = 110
max-spouse-gap = 25
min-marriage-age = 16
```

Unknown, duplicate or out-of-range thresholds are hard errors, never silent no-ops. The existing W301/W303/W302/W704 limits also move to `[lints.thresholds]` with their historical defaults, so behaviour is unchanged for anyone without the new section.

## Also

- Coverage floor raised 95% -> 96% regions (now 98.4%).

## v0.7.1 — 2026-09-10

Point release. 0.7.0 is what made `E005` stop being a dead rule, and the moving `v1` tag points at it, so an Action user got 140 new errors on an ordinary export without the repair that clears them. That repair landed just after the tag; this ships it.

## The one that matters

**`--fix` now repairs E005** ([#51](https://github.com/pmontp19/gedlint/issues/51)). Every occurrence on a real export was the same shape: a `CONT` or `CONC` sitting one level below another instead of beside it, usually a run getting one deeper each line. `E001` cannot see it, because each step is `+1` and legal on its own.

On a real 544-individual tree this takes `E005` from **140 to 0** and the exit code from **2 to 1**, so the file passes a `fail-on: error` gate after a single `--fix`, with every other rule's count unchanged.

A whole run collapses in one pass. The other branch of the rule, a `CONT` at level 0, is deliberately left alone: there is no parent to infer and inventing one would be guessing at your data.

## Web viewer

**Baseline support** ([#52](https://github.com/pmontp19/gedlint/issues/52)). Save a baseline, load it back, and findings split into what is new and what you have already seen. Known findings are grouped rather than hidden, resolved ones are surfaced, and the button becomes "Update baseline" so the ratchet is obvious.

A tree with a thousand findings was unusable for the audience the page exists for. This is what makes it adoptable without a terminal.

The saved file carries no line numbers, so inserting lines at the top of a tree does not invalidate it. Matching happens in the engine, so the browser and the CLI cannot disagree about what "already seen" means. The page still makes no network request of any kind.

## Housekeeping

The CI coverage floor moved from 84% to 95%, having sat far below actual coverage and protected nothing. `AGENTS.md` no longer carries counts or percentages: they had gone stale and sent people to solve problems that no longer existed, so the numbers now live where they are enforced.


## v0.7.0 — 2026-09-09

gedlint grows from a spec validator into a configurable linter with three surfaces over one engine: the CLI, the GitHub Action, and a **[web viewer](https://pmontp19.github.io/gedlint)** that runs the engine in your browser.

## For genealogists

The [web viewer](https://pmontp19.github.io/gedlint) checks a GEDCOM export before you import it, and repairs what is provably safe. Your file never leaves the tab: the page ships a Content-Security-Policy forbidding every network connection, so you can confirm it in devtools in five seconds. No account, no upload, no analytics.

## For anyone running it in anger

- **`gedlint.toml`**: presets and per-rule severity. GEDCOM has no comment syntax, so there is no inline suppression and never can be; configuration is the only way to silence a rule.
- **Baseline** (`--baseline` / `--write-baseline`): adopt gedlint on a messy tree and fail only on new findings. Keyed by rule and message fingerprint, never by line number, so inserting lines does not invalidate it.
- **Grouped output**: the default view collapses repeats by rule so a tree with 516 vendor tags no longer buries the eight broken parent-child links. `--verbose` restores the old per-occurrence listing.
- **`--explain CODE`**: what the rule means, what breaks in Gramps or RootsMagic when you ignore it, and what to do instead. The web page renders the same text from the same registry, so the two cannot disagree.
- **Two opt-in rulesets, off by default**: `hispanic-naming` (W6xx) and `hygiene` (W7xx). They encode conventions rather than the specification, so nothing fires unless you ask. `_MARNM` is never deleted and surnames are never re-cased by a bare `--fix`.
- **Selective repair**: `--fix --only CODE`, and `--fix --unsafe` for repairs that want human eyes.

## Correctness

- **E005 was a dead rule** and is fixed (#8). On a real 544-individual tree it now reports 140 genuine structural errors that neither the previous validator nor earlier gedlint could see: `CONT` lines nested under a `CONC`, where every level step is legal on its own.
- **`--fix` no longer applies rules you did not enable** (#44). It previously rewrote files it reported as clean.
- **`--fix` no longer leaves files the linter still rejects** (#36): the `CONC` rejoin was inserting trailing whitespace between the two halves of a UTF-8 character.
- **Output is deterministic** (#30). Whole-file findings used to print in `HashMap` order, so the same file could produce different output between runs.

## Under the hood

`src/lib.rs` split from one 2074-line file into modules with no behaviour change, verified by differential fuzzing. Repairs became data (`Edit` + `Applicability`), which is what makes interactive repair in the browser possible. Diagnostics carry byte-offset spans. The toolchain is pinned so `clippy` and `fmt` give the same answer locally and in CI.

Still zero dependencies.
