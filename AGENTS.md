# AGENTS.md: working rules for this repo (loaded every session, keep small)

Rules and pointers only. No counts, versions or coverage figures: they rot,
and a stale number here sends someone to solve a problem that no longer
exists. Numbers live where they are enforced.

## Non-obvious facts

- Working language is English (code, messages, docs). The owner's family research is Catalan; test *data* may be Catalan, test *names and comments* must not.
- The real fixtures live OUTSIDE this repo and contain living people. Never copy tree data into the repo, into issues, or into an agent's context. Discuss counts and rule codes only.
- `action.yml` renders annotations, the job summary and step outputs through `scripts/gh-report.js` (node, present on every GitHub-hosted runner). The zero-dependency rule covers the Rust binary, not the action.
- Release archives ship a `.sha256` and `action.yml` requires it by default. `require-checksum: false` is the only way to pin a release from before that existed.
- `cargo-llvm-cov` is installed; `cargo-mutants` is not. Mutation testing is manual, in a copy outside the tree; every survivor gets a regression test.
- `CHANGELOG.md` is generated by `scripts/changelog.sh` from the GitHub Releases. Never hand-edit it.

## Constraints (not derivable from code)

- Zero dependencies. No clap, serde or wasm-bindgen. Measured base speed matters and so does WASM reuse.
- The engine must stay free of fs/process/env/net so it compiles to `wasm32-unknown-unknown` unchanged. All I/O lives in `src/main.rs`.
- `--fix` only gets safe, invertible repairs, always with a `.bak`. Never "fix" semantics: dates, links, merges.
- Every repair is gated on configuration, so a rule that reports nothing repairs nothing. `tests/fixes.rs` ties the two surfaces together; keep it that way.
- No global diagnostic cap. A real export can bury errors under hundreds of vendor-tag infos, so limit output only via `--max`.
- Rule documentation lives once, in `src/registry.rs`. The CLI's `--explain` and the web viewer both render it, so they cannot disagree. Do not write rule prose anywhere else.
- This repo is private. Commit and push after every work unit.

## Quality gates

Run every step the `ci` job runs, and run clippy the way CI runs it: plain
`cargo clippy` does not deny warnings and will pass where CI fails.

```
cargo fmt --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo llvm-cov --summary-only --all-targets
cargo check --target wasm32-unknown-unknown
```

`.github/workflows/ci.yml` is the source of truth for what is gated,
including the coverage floor. Raise the floor there when you add covered
code; do not restate it here.

The toolchain is pinned in `rust-toolchain.toml` so every gate gives the
same answer locally and in CI. Without it, a laptop and a runner on
different stable releases disagree about clippy on the same commit, which
is worse than having no gate. Run `rustup update` after a new stable lands.

## Deferred roadmap (audited, consciously postponed)

- SLGC `FAMC` requirement and other LDS ordinance details beyond `STAT`+`DATE`.
- `W703` ships only the doubled-comma half of its specification. The URL-in-`PLAC` half was dropped so it would not double-report with the core `W401`; the rule name still promises more than it does.
- `U501`/`U502` flag the 5.5.1 to 7.0 upgrade path but do not perform it. Converting a tree between versions is a different product, and `--fix` may not touch semantics.
- No plugin runtime, deliberately (`docs/rfc-014-contract.md` section 0.2). Config addresses rules as `<ruleset>/<rule-name>`, so external rules could slot into the same namespace if demand ever appears.
